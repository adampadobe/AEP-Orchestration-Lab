Loyalty reward provider

Sandbox-aware reward fulfillment gateway for AJO Loyalty Challenges (private beta). Register the sandbox fulfillment URL in Loyalty admin, run setup scripts from your terminal, and monitor fulfillment requests received by the lab Cloud Run service.

Reward provider role

When a member completes a challenge task, AJO calls your registered fulfillment URL — you are a reward gateway, not a passive log collector. A production provider would credit points in a loyalty system, issue coupon codes, or update member balances via downstream APIs. This lab provider accepts the fulfillment payload, returns { "status": "accepted" }, and logs requests to an in-memory ledger (optionally sync to AEP loyalty.points is a future enhancement).

Progress tracking (e.g. buy 3 coffees) happens in AEP experience events + AJO, not in the reward provider. Send qualifying events for profiles in the challenge audience; AJO evaluates task progress and triggers fulfillment when the goal is met. This is the standard challenge pattern — not BYOD.

Connection

Adobe calls the fulfillment URL when a member earns a reward. Health checks use the lab Firebase proxy so the browser never needs direct cross-origin access.
