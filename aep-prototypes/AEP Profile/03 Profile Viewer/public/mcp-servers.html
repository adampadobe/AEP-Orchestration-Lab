Reference for Model Context Protocol servers used with this lab: what each Adobe MCP does, its documented endpoint URL, how it is usually enabled in Cursor, and where to read official setup guides. This page does not store or display credentials and is not Adobe-sandbox-dependent.

About MCP in Cursor

Model Context Protocol (MCP) lets Cursor (and other agents) call external tools with structured schemas instead of guessing APIs. This catalog is intentionally sandbox-independent UI: it remains available with no Adobe sandbox selected and can be used to plan non-AEP workflows too.

Adobe-hosted servers typically use streamable HTTP and OAuth (Adobe ID). Some integrations (Firebase, Express Developer) run as local stdio processes instead. Test mutating workflows in non-production sandboxes first; validate tool output before acting on it.

Configuration in this repository

.cursor/mcp.json in this repo currently enables only the Firebase MCP (npx -y firebase-tools@latest experimental:mcp). Adobe product MCPs are normally added in Cursor Settings → Tools & MCP (global) or an extended local mcp.json — see AGENTS.md in the repo root.

  • In this repo — committed project MCP (Firebase stdio).
  • Global / plugin — Adobe product MCPs (AEP Marketing Agent, Analytics, CJA, Target, AEM, Express Developer) when your org has entitlements.
  • Adobe documented — official guides for servers you can add (e.g. Marketo, custom App Builder MCP).
