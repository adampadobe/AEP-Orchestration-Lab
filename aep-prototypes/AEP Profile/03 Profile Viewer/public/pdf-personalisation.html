2. Success response

              
HTTP 202 means the request is validated and durably queued for PDF generation and email delivery.

              
{
  "status": "queued",
  "jobId": "6f442fca6b76330e4de4ded79e18fe718673fa52",
  "requestId": "booking-event-EK8F2Q-001",
  "templateName": "booking-confirmation",
  "campaignId": "30f45cd3-da50-436c-ae46-d0ab8f521f14",
  "acceptedAt": "2026-08-11T15:00:00.000Z",
  "reused": false
}

              
3. Failure response

              
{
  "status": "error",
  "error": "PDF_JOURNEY_TEMPLATE_INVALID",
  "message": "Unknown templateName. Use one of: booking-confirmation, checkin-confirmation."
}

            

          


          

            Built-in template names
            booking-confirmation
            checkin-confirmation
            For ra-boarding-pass-template, optionally map data.Barcode, data.FF_Image, and data.Offer to complete base64 image data URIs. Omitted image fields leave the DOCX placeholders unchanged.
            Use a stable event identifier for requestId. A retry must reuse it; a new booking or check-in must use a new value.
